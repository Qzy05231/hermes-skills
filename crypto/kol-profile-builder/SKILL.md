# KOL Profile Builder

一键生成加密KOL的结构化用户画像。

## When to Use

- 用户说「分析一下 @用户名」「给这个KOL做画像」「这个博主怎么样」
- 想要了解某个KOL的身份背景和可信度
- 追踪KOL追踪名单中的新成员
- 评估某个KOL是否值得长期关注

## Workflow

### Step 1: 采集原始数据

使用 browser_navigate 打开目标用户的 X 主页，从页面 DOM 提取数据。

**注意：** X 使用登录墙拦截未登录用户。你仍然可以从 profile 页快照中提取以下信息：

**可提取字段：**
- ✅ 显示名称（从 heading 元素获取）
- ✅ 用户名（从 URL 或页面文本获取）
- ✅ Bio / 个人简介（从 StaticText 获取）
- ✅ 认证类型（蓝标/金标/灰标 — 从 profile heading 后缀判断）
- ✅ 关注数、粉丝数、帖子数（从 link 元素获取）
- ✅ 加入时间（从 link 元素获取）
- ✅ 账号分类标签（如 "娱乐和休闲" 等）

**受限字段（需登录）：**
- ❌ 推文列表（未登录只能看到空状态 "尚未发帖"）
- ❌ 置顶推文
- ❌ following / followers 列表

**粉丝数判断影响力层级参考：**

| 粉丝数 | 层级 |
|--------|------|
| < 1万 | 微型 KOL / 早期 |
| 1万-5万 | 初级影响力 |
| 5万-20万 | 中腰部 |
| 20万-100万 | 头部 |
| > 100万 | 顶流 |

**关注/粉丝比分析：**
- 关注数 >> 粉丝数：处于内容积累期，或内容方向分散
- 粉丝数 >> 关注数：内容有吸引力，或已是成熟 KOL

### Step 2: 分析维度

#### 1️⃣ 身份标签
- **开发者 / 研究员 / 投资人 / 交易员 / 项目方 / 媒体 / OG**
- 关联项目名称（从 bio 中的链接、@提及判断）
- 技术背景 vs 市场背景（从 bio 用词判断）

#### 2️⃣ 影响力数据
| 指标 | 评估标准 |
|------|----------|
| < 1万粉 | 微型KOL / 早期 |
| 1万-5万 | 初级影响力 |
| 5万-20万 | 中腰部（@0xCygaar 级别） |
| 20万-100万 | 头部 |
| > 100万 | 顶流 |

**互动率评估：**
- 置顶推文点赞 / 粉丝数 比值（如果可获取的话）
- 近10条推文平均点赞（如果可获取的话）
- 是否有病毒式传播推文（点赞>1万）

**⚠️ 数据不足时的处理原则：**
当推文数据不可获取时，在画像中标注「数据不足，无法准确判断」，并基于 bio、名称、粉丝数等可用信息给出初步评估，避免过度推断。

#### 3️⃣ 关注领域
按主题分类（基于 bio + 名称关键词）：
- L2/基础设施、DeFi、NFT、AI×Crypto、GameFi、监管政策、宏观经济、土狗/Meme、技术开发
- 每个领域标注主/次
- 注意区分「加密领域」和「个人兴趣领域」
- 当推文不可见时，依赖 bio 中的关键词 + 名称暗示 + 关联项目推断

#### 4️⃣ 内容风格矩阵
| 维度 | 选项 |
|------|------|
| 技术深度 | ⭐ 小白友好 ↔ ⭐⭐⭐⭐⭐ 硬核技术 |
| 发布频率 | 每日多更 / 每日1条 / 不定期（帖子总数 ÷ 月数） |
| 语言 | 英文 / 中文 / 双语（从 bio 用词判断） |
| 内容形式 | 长线程 / 短推 / 图文 / 视频 |
| 情感基调 | 严肃分析 / 幽默段子 / 喊单激动 / 中立客观 |

#### 5️⃣ 核心观点 & 立场
- 持续输出的主题（3-5条，数据不足时标注待补充）
- 明确支持/反对的立场
- 是否有FUD/喊单倾向

#### 6️⃣ 可靠度评分 (1-5⭐)
| 维度 | 说明 |
|------|------|
| **技术深度** | 是否真懂技术，还是包装 |
| **信息准确度** | 过往预测/分析的准确率 |
| **诚信度** | 是否推广过rug项目，有没有利益冲突声明 |
| **实战价值** | 信息对投资/研究是否有用 |
| **独立性** | 是否客观，还是纯项目PR |

**可靠度评分原则：**
- 当数据不足以支持评分时，标注「—」或「数据不足」
- 低于1万粉的账号，信息准确度、实战价值、独立性维度的可信度天然较低，因为缺乏历史数据验证
- 每个评分需附带简短说明依据

### Step 4: 数据获取方法

**方法A — 浏览器（最推荐，数据最完整）：**
```javascript
// 1. 导航到 https://x.com/USERNAME
// 2. 从 snapshot 中提取 profile 信息
// 3. 如被登录墙挡住，使用 vision_analyze 截图分析页面
// 4. 用 browser_console 执行 JS 提取页面文本：
document.body.innerText.substring(0, 3000)

// 5. 遇到登录墙导致推文不可见时，如实标注
// 6. following 页面需要登录，未登录时无法抓取
```

**方法B — xurl（可能在中国网络下超时）：**
```bash
xurl /2/users/by/username/USERNAME --auth oauth2
xurl /2/users/by/username/USERNAME?user.fields=description,public_metrics,created_at,profile_image_url,verified_type --auth oauth2
```
⚠️ 中国网络下 xurl 可能超时，超时后回退到方法A

**方法C — xclaw（API 可能返回404）：**
```bash
curl -s -x http://127.0.0.1:7897 "https://api.xclaw.ai/v2/tweets?username=USERNAME&limit=20" \
  -H "x-api-key: $XCLAW_API_KEY"
```
⚠️ xclaw API 近期不稳定，常返回404。可以先尝试，404 回退到方法A

### 最佳实践：数据采集策略

推荐先用**方法A（浏览器）**获取基础 profile 信息，同时尝试方法B/C。无论哪种方法成功，都先落地基础画像，标注数据来源和局限性。用户如果有更多数据可以提供（截图、链接等），再进行增强。

## Pitfalls

1. **xclaw API不稳定** — 经常返回404，不要依赖它作为主要数据源。先用浏览器，xclaw 作为可选增强
2. **xurl 在中国网络下超时** — 如果超时，直接回退到浏览器方式。不要等待超过30秒
3. **X登录墙** — 未登录状态下只能看到 profile 基本信息（名称、bio、粉丝数），推文和 following 列表不可见。这是正常现象，如实标注即可
4. **数据不足时的报告** — 不要为了填充模板而过度推断。明确标注「数据不足，无法准确判断」
5. **数据时效** — 互动数据是即时的，画像应标注数据采集时间
6. **主观判断** — 可靠度评分是主观评估，需标注信息来源和依据
7. **AI生成的推文内容** — 部分KOL可能用AI代写，注意区分
8. **关注列表分析** — 关注数很大（>500）时，X 未登录状态下无法直接爬取。建议让用户登录后截图或提供关键词
